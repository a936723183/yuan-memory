# 渊 · 一套能"想起来"的记忆系统

> 只读你的记忆文件，自建索引，按需召回；可选再叠一层"图书馆"做分区、加密与语义检索。
> 不联网、不调模型、不改原件——删掉这个目录就等于什么都没发生。

---

## 它解决什么问题

上下文一满就失忆。但"记得更多"不是解法，**每次只取需要的**才是。

大多数 AI 记忆方案是三选一：把全部记忆塞进提示词（贵、吵、还会漏）、只存不取（写进去了，用的时候想不起来）、
或者依赖云端向量库（要账号、要钱、要联网）。

渊走第四条路：**本地索引 + 按需召回**。

- 记忆还是那些 Markdown / JSON 文件，渊一个字都不改；
- 它只在自己的 SQLite 里建一份"目录卡"：哪条在哪、讲了什么、有多重要；
- 需要时按一句话去查，几毫秒返回最相关的几条。

作者机器上的实测（800 条记忆量级）：**命中@6 = 100%，命中@3 ≈ 90%**，召回耗时 6 ms 量级。

## 两个组件，各管一层

| 组件 | 是什么 | 什么时候用 |
|---|---|---|
| **渊**（`bin/`） | 只读索引器：扫记忆文件建 FTS 索引，按问题召回 | 日常、单项目、工具型 AI |
| **记忆图书馆**（`library/`） | 记忆库本体：jsonl 真相源 + SQLite 缓存 + 分区 + 加密 + 向量精排 | 角色/伴侣型 AI、多来源、要隐私分级 |
| **DSH 插件**（`plugin/`） | 把图书馆的同步/检索/向量回填做成工具 + 设置页 | 装了 DeepSeek Harness 的话 |

一条原则贯穿三个组件：**真相只有一份，派生层随时可删。**

- 渊：记忆文件是真相，`yuan.db` 只是索引；
- 图书馆：jsonl 是真相，`memory.db` 只是缓存；
- 两者之间：**记忆卡是真相**，图书馆里的副本是派生。

## 渊怎么做到的

### 数据从哪来

`$DSH_HOME/memories/` 下五种文件，对应五条"轨"：

| track | 文件 | 初始重要性 |
|---|---|---|
| `key` | `projects/<id>/KEY.md` | 0.90 |
| `user` | `USER.md` | 0.85 |
| `memory` | `MEMORY.md` | 0.70 |
| `project` | `projects/<id>/MEMORY.md` | 0.55 |
| `daily` | `daily/YYYY-MM-DD.md` | 0.40 |

条目之间用单独一行 `§` 分隔，行首可带 `[2025-02-10 11:20] [shared]`。
格式很土，但好处是：**任何编辑器都能改，git 能 diff，人也能读**。

### 打分（这是全部魔法）

1. **候选**：问题切成中文二元组 + 英文词，剥掉问句口水（"上次 / 那个 / 什么"），FTS5 取前 60。
2. **打分**：

```
0.30 × BM25 排名
+ 0.38 × IDF 加权覆盖率      ← 泛词几乎不加分，罕见词说了算
+ 0.16 × 重要性
+ 0.09 × 新鲜度（120 天半衰）
+ 0.07 × 轨道权重
```

3. **出结果**：二元组 Jaccard > 0.75 视为同一条去重 → 取 top-k → 按字数预算截断。

**不需要定时任务**：每次召回先比对源文件 mtime+size，变过就静默增量重建，永远读不到旧索引。

## 记忆图书馆多了什么

| 能力 | 说明 |
|---|---|
| 双区域 | `dsh_zone`（工具记忆）/ `qq_zone`（角色记忆），互不污染 |
| 真相源 | append-only jsonl + manifest（代 + sha256），SQLite 可完整 rebuild |
| 写入队列 | 先落盘再入索引，失败进死信；`seq_alloc` 与写入同事务，防重复 id |
| 敏感加密 | `sensitive=true` 的条目用 Fernet 加密正文 |
| 索引对账 | `check` 查坏行/哈希/缺失；`purge` 记墓碑，不重写 jsonl |
| 向量精排 | 可选，接硅基流动或本地模型；不接也能用 FTS |

代价也写在 `library/OPS.md` 里：`secrets\content.key` 丢了敏感记忆就永久解不开；重建期间禁止写入；冲突检测仍是字面比对。

## 名字不叫「渊」就自锁

设计立场：**它叫渊，改名即篡改。**

- `manifest.json` 里写死名称与 HMAC 签名，代码不读配置、不认参数；
- 改清单（哪怕一个字）或把目录改名 → 判定篡改：
  - 写 `state/name-lock.json` 记录原因，
  - **焚毁索引**（`yuan.db` / `qqcard.db` / `memory.db`，纯派生、可重建），
  - 拒绝运行，退出码 3。
- **记忆源文件永远不碰**。锁的是身份，不是你的数据。

为什么"焚索引"而不是删数据：索引 100% 能从源重建，毁掉它足以让改名后的副本无法冒充渊，
又不至于造成不可逆损失。真正的自毁只会砸到作者自己的脚——误改名、搬家、从备份还原都会中招。

```bash
python bin/name_lock.py unlock --root .   # 恢复清单（目录名要自己改回 渊 / yuan*）
```

## 已知边界（不吹）

- **渊不懂同义**：字面匹配，"领证"搜不到"结婚"。`bin/synonyms.json` 能补一部分口语同义词。
- **图书馆的向量要外部服务**：本地模型或 API key，没配就只用 FTS。
- **查询太泛会散**：一句话塞三四个不相干主题，候选会互相挤。
- **中文为主**：二元组对中文友好，英文靠整词，别的语言未验证。
- **图书馆更重**：secrets 要单独备份、重建期禁写——收益是分区/加密/可重建，不是"更聪明"。
